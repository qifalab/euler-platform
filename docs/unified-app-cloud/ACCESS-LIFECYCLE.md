# 项目访问与资源保留

欧拉的人员会话、服务账号和应用公开接口有不同的认证边界。它们共享项目归属与应用启用状态，不共享凭据。所有实现只位于欧拉；原 EID、Trust 等独立项目无需变更。

## 人员与应用授权

浏览器管理 API 使用欧拉服务端会话，写操作还必须通过 CSRF 校验。团队和项目角色决定普通读取、写入、管理与密钥权限。EID / Trust 的认证审核、产品运营需要平台管理员单独授予 `review` / `admin`，团队所有者不会自动获得这两项授权。

`POST /api/v1/platform/grants` 接受原有字段以及可选 `expiresAt`（Unix 毫秒）。省略或设为 `0` 保持旧版长期授权兼容；未来时间表示定期授权，过去时间被拒绝。授权清单包含到期时间，包括已到期记录，便于管理员核查和撤销。每个应用请求都重新读取未到期授权，撤销和到期不依赖重新登录。重复授权仍需先撤销旧记录再建立新记录。

从项目移除成员会删除其应用授权；从团队移除成员会通过外键删除项目成员和应用授权。人员身份不会授予同名服务账号或其他项目账号。

## 服务账号

服务账号属于一个项目，由项目管理员创建。管理入口为：

| 方法 | 路径（相对于 `/api/v1/tenants/{tenantID}/projects/{projectID}`） | 行为 |
| --- | --- | --- |
| GET | `/service-accounts` | 列出账号、范围、期限、撤销状态及上次调用时间，不返回凭据摘要或密钥 |
| POST | `/service-accounts` | 创建账号并一次性返回 `{account, secret}` |
| POST | `/service-accounts/{id}/rotate` | 一次性返回 `{secret}`，旧密钥立即失效，保留原到期时间 |
| DELETE | `/service-accounts/{id}` | 撤销后续调用；保留账号记录与审计归属 |

创建示例：

```json
{
  "name": "daily-report",
  "expiresAt": "2027-01-01T00:00:00Z",
  "scopes": [
    {"applicationId": "statistics", "operations": ["read"]}
  ]
}
```

示例到期时间需要按部署日期调整，最长期限为创建时起一年左右（366 天）。每个项目最多保留 50 个尚未到期、未撤销的账号。密钥为随机生成的 `euler_sa_...`，数据库仅保留 SHA-256 摘要，创建或轮换时展示一次。前端不会将其放入本地存储。服务账号撤销不会删除它创建的业务资源。

支持 Database、Storage、Statistics、WeAuth 和 Lottery 的明确资源路由。范围中的 `read`、`write`、`manage`、`secrets` 分别授予，并不相互包含。服务器按应用、HTTP 方法及固定路由模板二次限制权限；并非授予某项范围后即可调用该应用的所有同名权限接口。

- `read` 允许对应资源清单、详情和报表；统计漏斗虽使用 POST，仍是读取操作。
- `write` 允许创建、内容更新、上传和活动操作；部分删除对象操作沿用 Storage 的内容写权限。
- `manage` 允许对应资源设置、删除和管理操作。Statistics 建站使用此范围。
- `secrets` 仅用于 Database / WeAuth 的资源密钥读取与轮换。它不允许创建欧拉服务账号，也不开放 Storage 长期访问密钥管理。

EID、Trust 的个人认证和人工审核，WitShield 调查与修复审批，以及所有应用的 `/admin/*` 运营接口均不开放给服务账号。服务账号的审计参与者始终是 `sa_*`，不会借用创建人的用户 ID。

机器 API 路径为：

```text
/api/v1/machine/tenants/{tenantID}/projects/{projectID}/apps/{applicationID}/{resourcePath}
```

必须通过 `Authorization: Bearer euler_sa_...` 调用。服务器拒绝携带 Cookie、Origin 或 X-CSRF-Token 的机器请求；普通浏览器管理 API 也拒绝服务账号密钥。SDK 应在服务端运行，不能把密钥注入浏览器。无效、到期或撤销密钥返回 401；范围不足或不允许的操作返回 403；跨项目请求返回 404。项目归档返回 409。已经被接受并开始执行的请求不因随后撤销而强制中断。

Python SDK 位于 `sdk/app-cloud-python`。平台集成测试通过真实 HTTP、SQLite 和原生 WeAuth 模块验证 SDK 的读写、范围不足、跨项目、Cookie 混用、密钥轮换和撤销，不使用模拟响应。

## 项目生命周期

项目列表和详情返回 `status: active | archived`。新增入口：

| 方法 | 项目相对路径 | 行为 |
| --- | --- | --- |
| GET | `/` | 查看项目详情和状态 |
| PATCH | `/` | `{name}` 更新名称 |
| POST | `/archive` | `{confirmation: "项目完整名称"}` 归档 |
| POST | `/restore` | 同样确认名称，恢复归档前的应用状态 |
| GET | `/export` | 下载不含秘密和业务内容的配置清单 |
| DELETE | `/` | 确认完整名称后删除已归档的空项目 |

归档事务先记录每个应用原先的启用状态，再将所有安装设为停用，并记录项目归档状态。恢复在一个事务里还原先前状态，原本停用的应用不会意外启用。数据库触发器阻止归档项目重新启用或新增启用安装，避免绕过 API 后重新开放公共入口。

归档后，原生应用、服务账号、公开业务接口和按安装状态检查的后台任务停止接受该项目的新工作。项目配置、授权、成员、审计、数据库、文件、设备数据及其他业务记录保留。平台管理员仍可查看配置、撤销服务账号、导出清单与恢复项目。

**归档只控制欧拉入口，不能代替外部资源隔离。** 已建立的 MySQL / PostgreSQL 连接、用户持有的数据库密码、直接公开的对象 URL、已签发的 S3 URL 和已经在途的操作不会自动撤回。需要完全停止基础设施访问时，部署方必须在数据库 / S3 / 设备侧另行撤销连接、密钥、公开策略及任务。外部对象存储的生命周期策略也独立运行。

## 删除与导出

包含应用安装或服务账号记录的项目不能删除，即使安装已经停用或账号已经撤销。没有隐式级联清理外部数据库、对象或业务内容的操作。这类项目应保留归档，未来若实现完整资源退役流程，需要逐项确认、释放外部资源并完成保留期处理。

空项目必须先归档并确认完整名称才能删除。项目审计保留在团队中。`DELETE /api/v1/tenants/{tenantID}` 仅允许所有者删除没有项目的团队，且必须确认团队完整名称；最终删除记录保留在独立 `deleted_tenants` 表，团队成员、邀请及团队内普通审计随空团队删除。

导出的 `euler-project-inventory/v1` 清单包含项目、应用安装、成员和服务账号元数据。它明确排除密钥、个人认证材料、业务数据、数据库内容、对象字节和设备证据。此清单用于配置核查，不是备份或恢复包；完整灾备必须使用部署备份流程并保留外部数据库、S3 与加密密钥。
