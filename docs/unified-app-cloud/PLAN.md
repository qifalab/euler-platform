# 欧拉独立应用平台：实施计划与完成标准

决策日期：2026-09-26。主仓库：`qifalab/euler-platform`。本轮按新的产品目标取代此前外部连接器基线；[完整架构契约](NATIVE-APPS.md)和产品功能矩阵是当前事实源。

## 目标与范围

以现有八个开源产品为功能和代码来源，在欧拉仓库内构建独立的统一应用平台。欧拉持有自己的业务数据、专用页面、应用服务、团队与项目授权。原项目继续独立开发和部署，本轮仅作只读参考，不修改其登录、数据库、仓库或生产配置。

欧拉使用独立的新版 E时代通行证 OIDC 客户端。各应用人员管理入口统一校验欧拉会话、项目成员关系、应用启用和产品权限。原站旧鉴权不参与欧拉人员登录；公开验证、报名、埋点、短期文件链接及设备签名保留各自限权协议。

## 实施阶段

### P0 功能盘点与独立边界

- [x] 固定八个原项目的源码版本，逐项核对可用业务功能、接口和页面。
- [x] 确认所有改动、测试、部署文档与合并仅位于欧拉。
- [x] 定义模块接口、可信 Scope、权限、持久化、审计及公开入口。
- [x] 保留复用代码的来源、许可证与 NOTICE。

### P1 统一身份与工作空间

- [x] OIDC 授权码、PKCE、state、nonce、签名验证及 HttpOnly 会话。
- [x] 团队、项目、邀请、成员角色、撤权、CSRF 与跨项目隔离。
- [x] 应用工作区、启用/停用、固定团队项目上下文及深链接校验。
- [x] 独立审核/运营授权，平台管理员按准确 provider/subject 配置。
- [x] 人员授权路径阻断旧连接器接口；无默认管理员和备用密码。

### P3 部署与验收

- [x] 非 root 容器、同源反向代理、真实 Widget 嵌入、配置样例与完整数据备份。
- [x] Go vet / race、Vue 类型检查与生产构建、真实 Go + SQLite 浏览器场景。
- [x] CI 提供独立 MySQL、PostgreSQL、S3、Unix socket 与 Docker 部署验收。

合并条件：当前提交全部远端 CI 通过后，按用户授权直接合并欧拉主分支。

实际执行结果与环境限制记录在 [VALIDATION.md](VALIDATION.md)，不能用旧连接器阶段的 CI 结果代替新应用的验证。

## 部署边界

上线仍需部署者提供欧拉独立 OIDC 客户端、HTTPS 地址、持久加密密钥及需要的数据库、S3、邮件、机器人和 AI 服务配置。缺少配置时明确不可用，不生成演示资源。当前控制面是单实例 SQLite；多副本、计费及历史生产数据导入需另行设计，不属于原项目既有业务功能。

本轮不迁移旧生产数据，不修改原 EID 鉴权，不部署生产。代码交付通过 [PR #3](https://github.com/qifalab/euler-platform/pull/3)；合并时以最新提交的完整检查为准。
