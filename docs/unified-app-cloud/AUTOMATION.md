# 应用联动与活动资格

欧拉使用自身的身份、项目、权限和数据库执行联动。原独立产品保持独立，本机制不访问或修改它们的生产实例。

## 已实现的两条流程

1. **认证或成员资格 → 项目资源包**。在“应用联动”选择明确的 Trust 方案，或本项目 EID 已确认录取的成员资格，指定同一团队中的目标项目、Database/Storage 应用与资源包模板。通过审核或确认录取产生新事件后，后台核验最新状态并发放一次性奖励。Trust 审核改为拒绝、方案停用或 EID 申请删除时，可终止由该规则授予的资源包。
2. **活动资格与防刷 → 报名 → 开奖 → 通知/权益**。活动设置可要求登录、指定 Trust 认证、EID 已确认成员资格，以及 WeAuth 人机验证。登录报名会将参与者绑定到欧拉账号；开奖后可按明确规则发站内通知或授予指定项目资源包。站内通知仅收件人可读取及标记已读。

报名默认保持匿名开放。仅启用 WeAuth 时仍支持匿名报名。资格条件会自动要求登录；登录报名者需已有当前团队和项目访问权限。公开报名链接只提供本次报名入口，不加入团队、不授予管理或审核权限。匿名、手动或批量添加的参与者没有经过验证的欧拉身份，因此不会触发个人通知或身份权益规则。

WeAuth 凭据在报名事务中消耗，绑定当前项目的站点、活动 action、欧拉公开域名、申请 IP 和有效期。来源应用停用、不同活动或 IP、过期或已使用凭据均拒绝报名。报名事务失败会回滚凭据消耗。

## 权限与权益语义

规则创建需要项目管理权限，并且创建人具备下列产品权限：

| 来源/动作 | 明确授权 |
| --- | --- |
| Trust 结果 | 当前项目 Trust `review` |
| EID 成员结果 | 当前项目 EID `review` |
| 活动中奖 | 当前项目 Lottery `manage` |
| 赠送资源包 | 目标项目对应应用 `admin` |

团队所有者身份本身不等于产品审核或运营授权。执行、手动重试和重新启用规则都会重新检查授权、授权有效期、项目归档状态和应用安装状态。执行使用规则原创建人的当前权限；另一位管理员重试不能替代原创建人授权。受益人也必须仍具有来源项目访问权限，领取资源包还需目标项目访问权限。

资源包增加的是**指定项目的共享配额**，不授予用户访问或管理权限。模板数量与有效期在授予时保存为不可变快照。**每人每条规则仅奖励一次**，到期、撤销或再次认证通过均不会重新发放或自动延期。新一期奖励应建立明确的新规则。撤销使资源包立即到期，不删除已有文件或数据库。活动中奖奖励保持模板有效期；已完成的抽奖记录不因开启新周期而失效。

规则暂停会取消未执行任务，不回收既有权益。权限被撤销或应用停用后，任务停止，既有权益继续按原有效期到期；恢复必要授权后可以手动重试失败任务。长期停用的来源应用不会被绕过以执行撤销操作。

规则只订阅创建后的事件，不追溯历史审核或旧抽奖。Trust 规则只在当前认证仍通过且方案启用时发放；EID 规则要求当前状态为 `offer_confirmed`。重复及乱序事件按数据库中的最新状态判断。

## 持久性与故障恢复

- 应用状态和 `automation_events` outbox 在同一 SQLite 事务中提交。事件只保存身份/资源标识、版本与状态，不包含材料、邮箱、附件或密钥。
- 分发事务按来源项目、事件类型、方案/活动匹配已启用规则，写入唯一 `(rule_id, event_id)` 执行记录。
- 工作线程每秒检查，单轮最多分发、执行各 100 个事件/任务。任务获取 60 秒租约与不可猜测租约令牌，进程崩溃后可接管过期租约。
- 资源包快照、唯一 `(rule_id, subject_id)` 回执、应用审计和任务完成状态在同一事务中提交。崩溃不会留下“已发资源但未记完成”导致的重复发放窗口。
- 暂时失败按尝试次数平方秒退避，最多自动尝试 5 次；权限、缺失对象或非法配置等确定性失败进入失败队列。错误记录使用受控文案，不保存原始连接错误。
- 管理员可在“执行记录”查看状态、次数与原因，修复授权/配置后显式重试。尝试次数不代表成功，只有 `succeeded` 表示事务已提交。暂停规则的任务显示 `cancelled`，当前不符合条件的通知显示 `skipped`。
- 整库备份包含规则、事件、任务、回执和通知。恢复数据库后启动工作线程即可继续，不依赖浏览器保持在线。主服务取消并等待线程结束后关闭数据库。

## 接口

前缀 `/api/v1/tenants/{tenantID}/projects/{projectID}/automation`。浏览器统一欧拉会话和 CSRF，不接受公开报名 token 作为管理凭据。

| 路径 | 用途 |
| --- | --- |
| `GET /rules` / `POST /rules` | 查看/创建规则 |
| `PATCH /rules/{id}` | `{ "enabled": false }` 暂停或重新启用 |
| `GET /executions` | 最近 200 条执行记录 |
| `POST /executions/{id}/retry` | 显式重试失败任务 |
| `GET /notifications` | 当前用户最近 100 条站内通知 |
| `POST /notifications/{id}/read` | 当前用户标记已读 |

规则示例：

```json
{
  "name": "研发资格奖励",
  "source": "trust.status",
  "filterId": "已存在的认证方案ID",
  "action": "package",
  "targetProjectId": "明确选择的目标项目ID",
  "targetApp": "database",
  "templateId": "已存在的资源包模板ID"
}
```

来源为 `eid.status` 时 `filterId` 固定为 `club`。来源为 `lottery.won` 时为活动 ID。`action: notify` 不需要资源包目标字段。

Lottery 原生接口另有 `GET/PUT /rooms/{id}/signup-policy` 与 `POST /rooms/{id}/signup`，登录入口为 `/apps/lottery?tenantId=…&projectId=…&signup=…`。

## 验收与边界

`internal/automation/engine_test.go` 使用真实 SQLite 与原生业务处理器验证审核→权益、资格报名→开奖→站内通知/权益、8 个并发处理线程、进程数据库重开、过期租约接管、事务回滚、资格乱序、撤权失败队列与显式重试、模板有效期。`internal/platform/automation_test.go` 验证实际平台授权到期、项目归档、会话/CSRF 与通知隔离。`internal/apps/lottery/signup_test.go` 通过实际 WeAuth 工作量证明验证活动/IP 绑定、单次消费及匿名防刷。

浏览器验收 `completion-automation.spec.ts` 在真实 OIDC 测试登录后，通过 UI 创建规则，真实审核并观察配额增加，再完成资格报名、开奖与通知已读。

当前动作限定为欧拉内部事务资源包和站内通知，未提供任意脚本、任意 URL Webhook 或通用流程语言。外部 SMTP/短信并未由本联动服务发送。真实通行证、邮件服务和生产基础设施仍需部署凭据与独立环境验收；本机制不会因测试完成而自动接入生产资源。
