# 欧拉独立应用平台：完整功能实施契约

决策日期：2026-09-26。本轮取代初版“分级外部连接”的产品目标。原项目仅作为功能和源码参照，所有新代码、测试、部署与合并只发生在 `qifalab/euler-platform`，不修改、不部署原项目。

## 产品边界

欧拉独立持有业务数据和应用能力。E时代通行证新版 OIDC 是人员登录身份源；欧拉负责会话、CSRF、团队、项目、权限及审计。原应用的登录、密码、旧 JWT、查询参数身份、全局 API Key 均不成为新欧拉的人员鉴权方式。机器密钥、验证 Widget、公开报名和埋点属于明确限权的数据接口，不用人员登录代替设备协议。

“全功能”以固定版本源码的可用业务功能为准，包括用户、审核、运营功能以及已有业务 API。原站框架自身的旧账号/密码/OAuth Toolkit 后台由欧拉身份权限管理取代；已发现的无鉴权全库重建等危险管理入口不会照搬。原站没有的 SQL 编辑器、对象版本管理等不冒充已存在能力。

## 实现结构

- `services/app-cloud/internal/appkit` 是统一身份/权限上下文与持久化边界。
- 应用分别实现于 `internal/apps/{eid,trust,weauth,database,storage,statistics,lottery,witshield}`。可复用原业务算法并保留出处；不能复制生产配置、固定管理员或演示授权。
- 默认采用同进程 Go 模块与持久化数据库。WitShield 可在欧拉目录内复用完整设备引擎，管理入口仍由欧拉授权，按项目隔离引擎数据；设备签名与人工审批状态机保留。
- 前端使用专用 Vue 应用页面，不把 JSON 调试器或外站跳转算作完成业务。所有页面采用当前团队/项目上下文，并复用表格、表单、弹窗和错误状态。
- 数据库直接管理部署者配置的 MySQL/PostgreSQL 引擎；存储直接使用配置的 S3/MinIO 数据面。这些是欧拉基础设施，不是调用原应用管理 API。

## 模块接口

每模块实现 `appkit.Module`，提供 `ID()`、`Migrate(context.Context)`、`Handler()`、`PublicHandler()`。构造函数统一为 `New(*appkit.Runtime) *Module`（可以返回具体类型）；初始化错误由 `Migrate` 返回。模块不得修改平台表定义；自己的表以产品名作为前缀，迁移应可重入。共享 SQLite 只有一个连接，事务内只用 `tx`，读取 Rows 后先关闭再查询。

人员路由挂载于 `/api/v1/tenants/{tenantID}/projects/{projectID}/apps/{applicationID}/...`。平台先校验 Cookie 会话、CSRF、当前成员角色、应用启用和必要权限，再注入 `appkit.Scope`；模块收到的 URL 路径为自身相对路径。模块不能信任 HTTP 身份头或请求体中的 user/tenant/project 字段。

模块必须对每个资源 ID 复核作用域。`appkit.Handle(mux, pattern, permission, endpoint)` 统一执行操作权限校验，业务写入与审计尽量同事务完成。外部操作需先记录意图，再记录实际结果；未知状态不能伪装成成功。

权限名固定为：`read`（当前项目可读）、`write`（项目成员以上）、`manage` 和 `secrets`（项目管理员以上）、`review`（独立产品审核授权）、`admin`（独立产品运营授权）。团队 owner/admin 不会自然获得 `review/admin`。个人资料、申请、材料和 Offer 还要校验 `ActorID`；审核权限单独授予。

公共业务入口在 `/public/{applicationID}/...`，不注入人员 Scope。各应用自行严格验证专用发布密钥、报名令牌或设备签名；不能从公开 token 推导管理权限。公共入口必须验证应用仍启用，限制请求大小和资源范围。

`Runtime` 提供平台数据库、持久数据目录、公开 URL、加密/解密及专用密钥派生。凭据、材料不会放入审计摘要；需显示的产品秘密通过独立权限接口和明确的查看操作提供，列表默认不包含秘密。

## 前端约定

各模块入口为 `platform/frontend/apps/console-base/src/cloud/apps/<app>/App.vue`，通过 `useApp()` 从 `../shared` 获取已选择应用上下文，调用相对业务 API。根工作区负责启用、权限加载和切换时取消旧请求。

专有业务在自己的目录内实现，不能写公共路由、CloudShell、go.mod 或根 Docker 配置。跨模块需求先通过公共契约协调。个人账号管理链接统一通行证；不为每个子应用再造备用密码。

## 验收

每产品需交付原功能逐项对应表、真实持久化业务测试与页面流程。跨项目 ID 猜测、viewer 写入、普通项目管理员调用运营/审核接口均需拒绝。数据库与存储必须测试真实引擎/S3行为；无法连接基础设施时明确报错，不返回虚拟资源。最终以完整工作流、设备审批边界、备份恢复、容器部署与 CI 通过为合并条件。用户已授权完成这些验收后直接合并欧拉主分支。
