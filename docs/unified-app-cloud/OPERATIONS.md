# 应用云运行与故障处理

本文对应欧拉独立应用云服务。原 EID、Trust 等项目的配置和部署不受影响。代码中的恢复机制和自动化测试不代表已完成生产身份源、邮件、AI、真实集群或灾备验收；实际生产连接和恢复演练必须在部署环境记录结果。

## 服务状态的含义

| 入口 | 访问权限 | 含义 |
| --- | --- | --- |
| `GET /healthz` | 公开 | HTTP 进程能响应，200；不代表依赖健康 |
| `GET /readyz` | 公开 | 核心 SQLite 可以响应且未进入关停，200；否则 503 |
| `GET /ops/diagnostics` | 平台管理员会话或独立运维 token | SQLite、可选数据库/S3、身份源的状态与检查时间 |
| `GET /ops/metrics` | 同上 | Prometheus 文本指标，包含请求数、耗时累计值、并发数、核心就绪、登录可用、依赖状态 |

可选 MySQL、PostgreSQL、S3 未配置或故障时，核心 `/readyz` 仍可能返回 200。这允许用户继续使用不依赖它们的应用。运维必须同时关注依赖告警，不能仅用 `/readyz` 宣称全部业务健康。身份提供方故障也不应把已有欧拉会话踢下线。

依赖状态为 `up`、`down`、`not_configured`、`configured_unverified` 或 `checking`。`not_configured` 与连接失败明确区分；`configured_unverified` 只说明配置存在。诊断不输出 DSN、URL、密钥或原始底层错误。依赖每 30 秒检查一次，每次有 3 秒期限；应同时检查 `checkedAt` 是否陈旧。核心就绪由每次请求现场检查，最长 2 秒。

数据库探测使用现有连接的 Ping；S3 使用只读列桶验证。它们不会创建测试资源，但通过探测仍不等于已验证创建、写入、配额、备份或恢复等全部权限。邮件、通知 webhook 和 WitShield AI 配置由相应应用/项目管理，当前无全局自动发送或推理探测；这些能力需要在各自工作台单独联调。

## 身份源故障与恢复

配置有效时，欧拉立即启动后台身份初始化。OIDC discovery 失败会按 1、2、4、8 秒等间隔重试，最大 60 秒；单次网络检查最长 15 秒。成功后每 60 秒重新检查。所有检查保持 issuer 精确匹配、HTTPS、签名算法和原有安全验证，不会为了恢复而降级信任。

初始化期间或后续 discovery 失败时：

- 新登录/回调返回 503 和固定错误，登录恢复后可以重试；已经建立的欧拉会话仍由自己的 SQLite 校验。
- 登出保持可用，仍要求原有 CSRF 校验。会话到期、被撤销或持久化不可用时不会继续授权。
- `/api/v1/session` 的 `authenticated` 与 `loginAvailable` 分别表示已有会话和发起新登录的状态，可同时为 `true`、`false`。
- `/ops/diagnostics` 的身份部分包含检查时间、最后成功时间和连续失败次数；不含提供方地址或凭据。

OIDC 的 `available` 是最近一次 discovery 成功，并非每次授权端点、token 端点、UserInfo 或 JWKS 都已经实时验证可用。短暂故障可能要到下一次检查才被观察到，实际登录仍严格验证并安全返回失败。

显式 `oauth2_userinfo` 模式没有 OIDC discovery，状态为 `configured_unverified`；允许发起登录，不假称已验证远端健康。配置缺失/非法不会自动读取其他应用的密钥或启用测试身份。环境变量配置不可变，改正配置或轮换凭据后需重启服务。

## 受保护监控

管理员浏览器访问要求真实欧拉会话，并且 `provider` 与 `subject` 必须同时匹配 `EULER_PLATFORM_ADMIN_IDENTITIES`。普通成员、项目管理员和应用管理员都不会因此获得全局运维访问权限。

监控系统可配置独立的 `EULER_OPERATIONS_TOKEN`，长度 32 至 4096 字节，建议随机生成至少 32 字节后使用 base64 编码，通过 `Authorization: Bearer …` 请求以上两个 `/ops/` 入口。该 token 只提供运维读取，不授权任何业务 API。未配置 token 时仅支持平台管理员会话；错误/重复 Authorization 头、query token、角色伪造头均不接受。反代需将 `/ops/` 转发至应用云，部署时全程使用 HTTPS，并在入口限制允许访问的监控网络。

可使用独立临时权限为 0600 的 curl 配置文件保存 Authorization 请求头，再执行 `curl --config <配置文件> https://<欧拉域名>/ops/diagnostics`。避免将实际 token 直接粘贴到共享终端记录、日志或工单。轮换该 token 后重启欧拉并同步监控端。

建议监控 `euler_ready`、`euler_identity_login_available`、`euler_dependency_state`，并设置持续不可用与检查陈旧告警。请求计数标签仅包括固定路由类别、标准 HTTP 方法和状态码，避免无限标签数量。`euler_http_duration_seconds_sum` 配合 `euler_http_requests_total` 可计算平均延迟；当前不提供延迟分位数直方图，也不提供跨服务分布式追踪。

## 请求排障与数据保护

每个响应包含服务端随机生成的 `X-Request-ID`，对应 JSON 请求日志中的 `requestId`。服务端不信任调用方提供的请求 ID。日志仅记录固定路由类别（`auth`、`api`、`public`、`ops`、`probe`、`other`）、标准方法、状态码和处理耗时。

不记录请求 URL、路径参数、query、Authorization、Cookie、请求/响应正文或 panic 原文。这样 OAuth code/state、活动邀请 token、对象存储键以及用户字段不会因访问日志泄露。向维护者提交故障时给出时间、请求 ID、所处工作台与错误提示即可。反代、CDN、数据库和外部身份服务的日志有各自配置，必须分别关闭敏感 query/正文记录；应用日志策略不会自动修改它们。

## 关停、备份与生产验证

启动时先校验各应用已记录的数据结构版本，再执行模块迁移；所有模块迁移成功后才记录本次版本。版本不兼容会中止启动，避免旧程序误写新数据结构。升级前仍需完成备份，不能用修改版本记录绕过兼容性检查。

实现 `Maintain(context.Context) error` 的模块由服务统一调度，启动后立即执行一次，然后每小时执行，每次最长 5 分钟，并随停服取消。目前统计模块使用这一入口按站点留存配置清理历史记录；每次为有界批次，大规模积压可能需要多个周期。某次失败会记录固定模块名，后续周期继续尝试，不把原始 SQL/字段值写进日志。

SIGTERM/SIGINT 后服务先标记不就绪、取消后台 worker，再给 HTTP 请求最多 20 秒完成。身份初始化、依赖监控和自动联动 runner 都会等待退出，然后关闭模块及 SQLite，避免工作线程在数据库已关闭后继续写入。

单实例 SQLite 仍是当前控制面部署方式。不要给同一文件挂载多个读写副本。备份应覆盖控制面数据库、应用目录及独立保管的加密密钥，外部业务数据库和 S3 数据还需各自备份策略。恢复后必须验证身份关联、权限、加密字段、原生应用数据和外部资源映射；只检查服务能启动不足以证明恢复完整。

本次自动化覆盖 OIDC 初次故障重试、真实登录后的故障与恢复、故障时会话和登出、并发状态读取、取消网络请求、依赖降级与恢复、运维授权、请求日志脱敏和指标并发。这些结果适用于代码级故障模拟。真实新版通行证、邮件送达、AI 服务质量、生产容量、RPO/RTO 和独立组织试运行仍应由实际部署验收记录证明。
