# Statistics 日期分析、事件、转化与留存

Statistics 仍独立作用于欧拉的团队、项目和安装实例。原站点、PV/UV、URL 排行、tracker/widget/helper 路径兼容；原项目无需修改。新版控制台在“趋势、事件与漏斗”提供日期筛选、日趋势 SVG 与可展开数据表、来源/设备/浏览器、页面排行、事件列表、漏斗表单、CSV 下载和留存管理。

## 指标与时间定义

- 日期参数 `from`、`to` 使用 `YYYY-MM-DD`，包含两端自然日；`timezone` 使用 IANA 名称，默认 `UTC`。前端默认浏览器时区，明确显示且允许编辑。最宽 366 个自然日。
- 统计时间采用固定 9 位小数 UTC，兼容迁移保留旧数据的纳秒精度；后端把边界转换为 UTC，查询为 `[开始日当地零点, 结束日次日当地零点)`；DST 日可能只有 23 小时或有 25 小时。响应中的 `startInclusive`、`endExclusive` 是实际生效范围，可能因留存而缩短。
- 报表 UV 对所选区间、单一站点的 HMAC 访客标识去重。每日 UV 只在各日内去重，不能相加得到区间 UV。没有跨站身份关联，不以 IP 代替访客。
- 旧 `/report` 不带日期参数时返回**仍在留存范围内**的累计 PV、UV 和分页 URL 排行。带参数时改为所选区间。`page-views` 公开接口路径与响应格式保持兼容，计数同样遵循留存。
- 来源为已清洗 Referrer 的主机名（无查询参数与片段），无来源为“直接访问”。设备与浏览器是 User-Agent 的粗分类，可被伪造，不能当成安全凭证；机器人单列，不默认从 PV 中扣除。
- 一个分析或漏斗请求最多读取 200000 条记录；超出时明确拒绝并要求缩小日期范围，不展示静默抽样或截断的总数。页面展示来源前 10 项，CSV 包含全部聚合项。

## 自定义事件

管理员先在 `/sites/{id}/settings` 登记允许的事件名。最多 32 个，正则 `^[a-z][a-z0-9_]{0,39}$`，不得重复。名称描述稳定业务动作，例如 `signup_started`、`signup_completed`，不要把人名、邮箱或订单标识放进名称。

站点安装现有 tracker 脚本后可调用：

```js
// 与页面采集复用站点级随机访客标识；不会提交额外用户属性。
await window.eulerTrackEvent('signup_completed');
```

公开 `POST /public/statistics/sites/{publicId}/events` 只接受 `visitor_id`、`url`、`name`。未知字段（包括 `properties`、邮箱、客户端时间）一律拒绝；事件名必须预注册；时间由服务器生成。仅保存访客和 IP 的站点隔离 HMAC。URL 去掉查询参数和片段，但**网站不应把个人信息放在 URL 路径或页面标题中**；既有页面采集会保留清洗后的路径与标题。

采集继续验证安装启用、站点启用、精确来源域和页面地址匹配。事件请求体上限 8 KiB，页面采集 16 KiB。两者合计每站点、每来源 IP 每分钟最多 120 条；每站点每天 UTC 最多 100000 条，达到限额返回 429。公共 ID 只用于采集，不授予读取分析或管理权限。移除事件名后拒绝新的同名事件，留存期内的历史数据继续可分析。

## 漏斗语义

`POST /sites/{id}/funnel` 使用与分析相同的日期参数，提交 `steps`（2–8 个事件名，可重复）和 `windowMinutes`（1–10080）。

每位访客必须在同一站点内按服务器记录顺序完成前缀步骤。所有步骤都须落在选定日期区间，末步距首步不超过窗口；一位访客在每步最多计一次。同一事件记录不能同时满足两个重复步骤。同一时间戳按采集 ID 排序。多次首步会保留可行的新尝试；不把不同访客、不同站点的事件拼成一次转化。转化率分母为第一步人数。

漏斗不依赖页面 PV，不进行跨设备身份合并；关闭或清空浏览器 localStorage 会产生新的访客。事件只是客户端自报分析数据，不作为支付、授权或履约依据。

## 留存与清理

每站点默认保留 365 天，可设为 7–730 天。所有报表立即应用滚动留存边界。缩短留存会永久删除超期明细，前端要求明确确认。

保存设置、采集、读取报表都会执行有界分批清理。模块还实现 `Maintain(context.Context) error`，由欧拉生命周期维护任务在启动和周期运行时调用，包括停用、无人访问的站点；单轮每站点每张表最多清理 10000 条。后台未处理完的大积压不参与报表。管理员可 `POST /sites/{id}/cleanup` 重复执行分批清理；返回删除条数。后台维护受服务关闭 context 控制。

SQLite 的物理文件大小不一定随删除立即缩小；不要在请求路径执行阻塞的 `VACUUM`。按部署维护窗口与备份方案回收数据库文件空间。

## 接口与授权

以下路径相对于欧拉项目 Statistics 应用 API。保持统一项目范围校验。

| 方法与路径 | 权限 | 行为 |
| --- | --- | --- |
| `GET /sites/{id}/report` | read | 兼容 PV/UV 和分页 URL 排行，支持日期参数 |
| `GET /sites/{id}/analytics` | read | 有界日期趋势、来源、设备、浏览器、页面、事件聚合 |
| `GET /sites/{id}/export.csv` | read | 相同日期范围，导出每日指标与全部聚合项 |
| `POST /sites/{id}/funnel` | read | 只读计算顺序漏斗（仍经过平台 CSRF 校验） |
| `GET /sites/{id}/settings` | read | 留存及事件登记 |
| `PUT /sites/{id}/settings` | manage | 保存设置、清理过期数据，审计与变更同事务 |
| `POST /sites/{id}/cleanup` | manage | 清理过期数据并写审计 |

CSV 只包含聚合数据，不导出访客/IP HMAC。所有可控文本单元格都会忽略前导空白后检查公式前缀 `= + - @`，并转义公式前缀或控制字符；响应 `no-store` 且作为附件下载。

`go test -race ./internal/apps/statistics` 使用真实 SQLite，验证：旧时间格式迁移、纳秒级日期边界、区间 UV 去重、时区午夜边界、DST、跨站和项目隔离、预注册事件与拒绝额外属性、PV/事件共享限流、安装/站点停用拒绝、同访客有序漏斗、时间窗和重复步骤、留存隔离、闲置站点维护、CSV 公式注入、读者不能修改设置。

前端 `AnalyticsPanel.test.ts` 验证可视化与日期筛选、旧数据清空、实际 CSV 下载调用、漏斗表单、只读权限，以及缩短留存确认。上线仍须按真实访问规模衡量查询时延、数据库容量和采集限额。
